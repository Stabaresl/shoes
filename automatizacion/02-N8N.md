# 02 — Configurar n8n e importar los flujos

Aquí trabajas en tu n8n local. Antes de empezar deberías tener listos los datos
de `01-META.md` §1–§5.

---

## §1. Darle una URL pública a tu n8n

Meta tiene que poder llamar a tu n8n desde internet, y `localhost` no le sirve.
Necesitas un túnel: un dominio público que apunte a tu máquina.

### Opción recomendada: Cloudflare Tunnel (gratis, estable)

- [ ] Descarga `cloudflared` desde
      `github.com/cloudflare/cloudflared/releases` (para Windows: `cloudflared-windows-amd64.exe`).
- [ ] Abre una terminal **aparte** (esta se queda corriendo) y ejecuta:

  ```powershell
  .\cloudflared.exe tunnel --url http://localhost:5678
  ```

- [ ] Te imprime una URL tipo `https://algo-random.trycloudflare.com`. **Cópiala.**

> Con el túnel gratuito, la URL **cambia cada vez que lo reinicias**, y cada vez
> tendrás que actualizarla en Meta (`01-META.md` §6). Para algo estable: crea un
> túnel con nombre asociado a un dominio propio (también gratis con una cuenta de
> Cloudflare), o mueve n8n a un VPS.

### Alternativa rápida para una prueba

Si solo quieres probar un rato, n8n trae túnel propio:

```powershell
n8n start --tunnel
```

No lo dejes así de forma permanente: la propia n8n lo desaconseja para producción.

### Decirle a n8n cuál es su URL pública

Sin esto, n8n te muestra URLs de webhook con `localhost` y Meta no podrá verificarlas.

- [ ] Detén n8n.
- [ ] Define la variable de entorno y vuelve a arrancarlo:

  ```powershell
  $env:WEBHOOK_URL = "https://algo-random.trycloudflare.com"
  n8n start
  ```

  Si usas Docker, añade `-e WEBHOOK_URL=https://algo-random.trycloudflare.com`
  a tu `docker run`, o la línea equivalente en tu `docker-compose.yml`.

- [ ] Comprueba: abre cualquier nodo Webhook en n8n; la URL que muestra debe
      empezar por tu dominio público, no por `localhost`.

## §2. Crear las dos credenciales

Los tokens **no van dentro de los flujos**: van en credenciales de n8n, cifradas.

### 2.1 Token de la página de Facebook

- [ ] En n8n: **Credentials → Add credential**.
- [ ] Busca y elige **Query Auth**.
- [ ] Rellena:
  - **Name** (arriba, el nombre de la credencial): `Facebook Page Token`
  - **Name** (el campo del formulario): `access_token`
  - **Value**: el token de página de `01-META.md` §4.3
- [ ] Guardar.

> Se llama "Query Auth" porque Meta espera el token como parámetro `?access_token=`
> en la URL. n8n lo añade solo a cada petición.

### 2.2 Clave de Claude

- [ ] **Credentials → Add credential → Header Auth**.
- [ ] Rellena:
  - **Name** (de la credencial): `Anthropic API Key`
  - **Name** (del campo): `x-api-key`
  - **Value**: tu clave `sk-ant-...`
- [ ] Guardar.

## §3. Elegir el valor de `CATALOGO_URL`

Los flujos leen el catálogo de tu web. Qué URL poner depende de **cómo corre n8n**:

| Cómo tienes n8n | `CATALOGO_URL` |
|---|---|
| Instalado con npm, directo en Windows | `http://localhost:3000/api/catalogo` |
| En Docker (Docker Desktop) | `http://host.docker.internal:3000/api/catalogo` |
| La web ya publicada en internet | `https://tudominio.com/api/catalogo` |

Los flujos vienen con la variante de Docker puesta. **Cámbiala si no usas Docker.**

- [ ] Arranca la web para que el endpoint exista:

  ```powershell
  npm run dev
  ```

- [ ] Compruébalo en el navegador: `http://localhost:3000/api/catalogo`
      Debe devolver un JSON con `"total": 63`.

> La web tiene que estar corriendo cada vez que se dispare un flujo. Cuando la
> publiques en internet (Vercel u otro), cambia `CATALOGO_URL` al dominio real y
> deja de depender de tu PC. Añade también `SITIO_URL=https://tudominio.com` en
> `.env.local` para que los enlaces de las publicaciones salgan correctos.

## §4. Importar y configurar los flujos

Repite esto **para cada uno** de los dos archivos de `automatizacion/n8n/`.

- [ ] En n8n: menú **⋮ → Import from File** (o *Workflows → Import from File*).
- [ ] Selecciona `workflow-1-publicacion-facebook.json`.
- [ ] Abre el nodo **"Configuración"** (el segundo de la izquierda) y rellena:

  | Campo | Qué pones |
  |---|---|
  | `PAGE_ID` | el ID de tu página |
  | `GRAPH_VERSION` | la versión de tu panel de Meta, ej. `v23.0` |
  | `CATALOGO_URL` | la del §3 |
  | `WHATSAPP` | tu número, formato internacional sin `+`: `573122651224` |

- [ ] Abre el nodo **"Publicar en Facebook"** y en **Credential for Query Auth**
      selecciona `Facebook Page Token`.
- [ ] Guarda el workflow.

Ahora el segundo archivo:

- [ ] Importa `workflow-2-messenger-bot.json`.
- [ ] Rellena su nodo **"Configuración"** con los mismos cuatro valores.
- [ ] Selecciona la credencial `Facebook Page Token` en **dos** nodos:
      **"Responder en Messenger"** y **"Botón de WhatsApp"**.
- [ ] Selecciona la credencial `Anthropic API Key` en el nodo **"Consultar a Claude"**.
- [ ] Guarda.

### Ajustar el horario de publicación

En el workflow 1, el nodo **"Horario de publicación"** trae `0 9,13,19 * * *`:
tres publicaciones diarias, a las 9:00, 13:00 y 19:00.

Para cambiarlo, edita esa expresión cron. Ejemplos:

| Quieres | Expresión |
|---|---|
| Una vez al día a las 10:00 | `0 10 * * *` |
| Dos veces: 8:00 y 18:00 | `0 8,18 * * *` |
| Cada 6 horas | `0 */6 * * *` |
| Solo días hábiles, 12:00 | `0 12 * * 1-5` |

> El horario es el del reloj de la máquina donde corre n8n.

## §5. Activar

- [ ] Abre el **workflow 2 (bot de Messenger)** y ponlo en **Active** (interruptor
      arriba a la derecha).
- [ ] Abre el nodo **"Verificación de Meta"** y copia la **Production URL**.
      Debe verse así: `https://algo.trycloudflare.com/webhook/messenger`
- [ ] Con esa URL, ve a hacer `01-META.md` §6.

Deja el **workflow 1 (publicación) inactivo** hasta que hayas probado a mano y
hayas cargado los precios reales. Lo activas cuando estés listo.

> **Production URL vs Test URL:** n8n muestra dos. La de test (`/webhook-test/`)
> solo funciona mientras tienes el editor abierto escuchando, y sirve para depurar.
> A Meta se le da siempre la **Production URL**, y para que funcione el workflow
> tiene que estar **activo**.

## §6. Si tocas los flujos

Los dos JSON los genera un script, para no editar JSON a mano:

```powershell
node automatizacion/_generar-workflows.js
```

Si cambias algo desde la interfaz de n8n, esos cambios **no vuelven** al script.
Decide dónde quieres que viva la verdad:

- **Cambios pequeños** (horario, textos, número de WhatsApp): hazlos en n8n y ya.
- **Cambios estructurales** (nodos nuevos, lógica): hazlos en el script,
  regenera y reimporta.
